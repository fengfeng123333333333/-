## 二、本步要解决什么

S1 的「开始任务」只写日志。S4 把它变成真的：

1. 点「开始任务」→ 队列里的待执行任务真的被调度。
2. 并发数与启动间隔从配置读，不是常量。
3. 停止能打断，未开始的标记中断。
4. 状态与结果实时回写到界面（跨线程）。
5. 每个任务执行完，浏览器**一定**被关掉（异常路径也要关）。
6. 失败必须留下可复查的东西：中文原因 + 页面 URL + 截图路径。

### 6.3 过程中发现并修掉的缺陷

1. **账号清单的 `user-data-dir` 整列读不到**。列名归一化时只对候选名去掉了连字符，表头没去，导致 `user-data-dir` 永远匹配不上 `userdatadir`，profile 路径读成空字符串。表现是「清单明明填了路径，日志却说路径为空」。7 条测试同时红，改 `NormalizeHeader` 两边统一归一化后修复。
2. **状态列只有一个 8×8 色点，没有文字**。这是 S1 留下的界面问题：队列行看不出「待执行 / 执行中 / 失败」，只看到一个颜色。真机验收时 UIA 完全读不到状态，才暴露出来。已改为「色点 + 状态文字」，列宽 56→76，任务列 180→160（总宽不变）。这不只是给测试看的——色弱用户和读屏软件同样读不到纯色块。
3. **中断路径没有日志**。取消后状态确实变成「中断」，但日志里查不到任何记录，事后无法区分「人按了停止」和「浏览器自己崩了」。已补两处日志（未开始即被停止 / 执行中被停止并记已运行时长）。
4. **并发计数非原子**。`counters.Succeeded++` 在多线程下会丢计数（并发 2 就可能出错）。在并发测试前就改成了 `Interlocked.Increment`。

### 6.4 踩的坑（工具类）

1. **UIA 用全窗口搜 `DataItem` 抓到的是左栏任务类型**，不是队列行。左栏 `ItemsControl` 的项也是 `DataItem`，5 个任务类型被当成了 5 条队列。改为按 `x:Name="TaskList"` 定位 ListBox 再取 `children()`。
2. **`click_input()` 会点空**。有一次点「添加任务」完全没反应，日志一行没有——窗口刚起来、焦点未稳时，坐标点击不可靠。改用 UIA 的 `InvokePattern`（`btn.invoke()`），直接调控件动作，不经过鼠标。
3. **改完代码只 build 了测试项目**，Presentation 输出目录还是旧 DLL，真机验收跑的是带 bug 的版本，白排查一轮。教训：真机验收前必须 `build FbAuto.slnx`，不能只 `build tests`。

### 6.6 与计划 PPT 的口径差异

计划 P08 把 S4 定义为「视频上传：六动作跑通」，验收是「10 条视频成功率 ≥8」。
本步做的是它的前置：**队列调度与执行链路**，页面动作一行未写。

这不是绕过验收，而是顺序问题——页面动作依赖 facebook.com 可达（本机 443 不通）且依赖账号登录态，
而调度、并发、取消、状态回写这些是本机就能验完的、且后面每条主线都要复用的部分。
先把这层跑稳，页面层才有地方挂。
