# 在境外云主机上做真机验收（A 方案）

> 目的：这台机器连不上 `facebook.com`，所以把「运行环境」搬到境外去，
> 而不是去改本机网络。程序全部文件都落在自身目录（见第 4 节），整包拷走即可。
>
> 本文只写「怎么做」。验收要记什么，见第 12 节的记录表。

---

## 0. 三条先看清

1. **发布包是自包含的**：目标机器**不需要**装 .NET 运行时（包里有 `coreclr.dll`）。
   需要装的只有 Chrome 和（如果要验比特通道）比特浏览器。
2. **`license.dat` 不随包走**。凭证用机器码派生的密钥加密，拷到别的机器解不开。
   云主机上首次启动会弹激活窗，贴**同一个授权码**即可 —— 码本身不含机器绑定，
   30 天从**本机首次激活**起算，所以在云主机上会重新获得完整有效期。
   （这是离线授权的固有限制，已记录，不在本次验收范围。）
3. **必须先人工在云主机的 Chrome 里登录一次 FB**，再跑自动化。
   自动化用的是已有浏览器配置里的登录态，它不会替你登录。见第 6 节。

## 2. 连上去

1. 云控制台里给实例绑定**公网 IP**（或 EIP）。
2. **安全组放行 3389**，来源填**你自己的出口 IP**（不要填 `0.0.0.0/0`，
   公网上的 RDP 爆破很快）。Windows 镜像默认可能只放行了 3389 给内网。
3. 本机开「远程桌面连接」（`mstsc`），地址填公网 IP，用户 `Administrator`，
   密码是买机器时设的那个。
4. 连不上时的兜底顺序：
   - 先用云控制台的 **VNC / Web 终端**登进去，确认机器活着、RDP 服务在跑；
   - 检查安全组端口；
   - 检查 Windows 防火墙的「远程桌面」入站规则。

> 首次登录后把「服务器管理器」的自动弹出关掉，它会一直挡着桌面。

**RDP 会话有三条实操注意**（跑任务时都会踩到）：

- **不要「注销」，只能最小化或直接关 RDP 窗口**。注销会结束会话，界面程序随之退出；
  关窗口（断开连接）会话保留，程序继续跑。
- **跑任务时保持 RDP 连着**。有头浏览器在断开的会话里截屏可能拿到空白图，
  失败截图就成了废图，排障时会误判成「页面是白的」。
- **别在跑任务时调分辨率或做全屏切换**，Playwright 的点击坐标会失效。

## 3. 装依赖

**Chrome（必须）**

- 装官方版本，装到默认路径。程序会自动在注册表和标准路径里找 `chrome.exe`
  （`ChromeLocator`），不用手工配。
- 装完手动启动一次，走完首次运行的引导（默认浏览器询问之类）。
- 如果装在非默认位置（免安装版），记下 `chrome.exe` 全路径，
  在程序「基础设置」页的 **Chrome 路径** 里点「选择...」填上。

**比特浏览器（只有要验比特通道才需要）**

- 装官方客户端并登录你的账号，保持客户端运行（本地接口是 `http://127.0.0.1:54345`）。
- 验收脚本/文档里凡是 `bit` 通道的任务，都依赖它在线。

## 4. 把程序拷过去

本机先打发布包（代码有改动时必须重新打）：

```
build\publish.cmd
```

产物在 `build\dist\FbAuto\`，约 220MB / 268 个文件。**整个目录**拷到云主机，
放 `C:\FbAuto\`。

> **注意：轻量应用服务器只有一个 60G 系统盘，就是 C 盘，没有 D 盘。**
> 本文早期版本写的 `D:\FbAuto\` 是错的（按「系统盘 + 数据盘」的常规 CVM 习惯假设的），
> 轻量默认不配数据盘，也不会自动出现 D 盘。放 `C:\FbAuto\` 没问题：
> 非受保护目录、Administrator 可写，路径也短。
> **不要放 `C:\Program Files`** —— 那会把配置和日志写到 UAC 虚拟化目录里，排障时找不到。

传输方式二选一：

- 远程桌面里直接复制粘贴文件夹（< 2G 时最省事）；
- 传到 OSS/网盘，在云主机里下载。

拷完检查三样在不在：

```
C:\FbAuto\FbAuto.Presentation.exe
C:\FbAuto\.playwright\node\win32_x64\node.exe   ← Playwright 驱动，缺了页面操作全废
C:\FbAuto\accounts.sample.csv
```

> 注意驱动路径是 `.playwright\node\win32_x64\node.exe`，**没有** `.playwright\node\node.exe`。
> 按常识猜路径会得出「驱动缺失」的错误结论（本项目的自检脚本第一版就这么误报过）。

> 程序**不要**放在「桌面」或临时目录：配置、日志、截图都写在 exe 同目录，
> 放桌面容易被误删。也不要放 `C:\Program Files`（UAC 虚拟化会把写入重定向走）。
> `C:\FbAuto\` 是本项目在境外云主机上的标准位置。

## 4.5 跑一次环境自检（必做，先于其他一切）

包里有 `check-env.cmd`。**双击它**，等约 1 分钟，同目录会生成 `env-report.txt`。

它一次性采集这些，省得一项一项问：

| 报告里的键 | 判据 | 不满足会怎样 |
| :-- | :-- | :-- |
| `is.admin` | True | 装 Chrome、改时区可能被拦 |
| `timezone` | 账号常用时区（如 `China Standard Time UTC+8`） | 「定时发布」差时区小时数 |
| `chrome.path` / `chrome.version` | 不是 `NOT FOUND` | 一条任务都跑不起来 |
| `.playwright\node.exe` | True | 页面操作全废，但报错写的是「浏览器起不来」 |
| `.playwright\cli.js` | True | 同上 |
| `coreclr.dll` | True | 说明包不完整，重拷 |
| `https://www.facebook.com/` | `HTTP 200` | 网络没通，别往下走 |
| `egress.location` | HK / SG | 出口地区要和账号常用地一致 |
| `bit.api.54345` | 只有验比特通道才需要 `REACHABLE` | 比特那支任务全失败 |

另外 `config.json.exists` / `license.dat.exists` 第一次跑应该是 `False`（还没激活），
`accounts.csv.exists` 在填好清单前也是 `False`，都属正常。

**把 `env-report.txt` 的内容发给技术对接人再往下走** —— 报告里任一项是红的，
后面的步骤都会以奇怪的方式失败，先修环境比先跑任务省时间。

## 5. 首次启动与激活

先解决**授权码从哪来**。码不含机器绑定，本机激活用的那张码在云主机上直接可用
（30 天从本机首次激活重新起算）。如果那张码丢了，用签发工具重签一张：

```
set FBAUTO_KEY_PASS=你的私钥口令
build\dotnet.cmd build tools\FbAuto.Keygen\FbAuto.Keygen.csproj -c Debug
build\dotnet.cmd run --project tools\FbAuto.Keygen --no-build -- gen --count 1 --days 30 --out 新码.txt
```

> 私钥在 `C:\Users\<用户>\FbAutoSecrets\license_private.key`，口令只有持有者知道。
> **私钥丢了，所有已发出的码都无法续期，也无法再签新码** —— 备份比什么都重要。
> `--count 1` 是签一张；批量签就把数字改大，码会写到 `--out` 指定的文件。

双击 `FbAuto.Presentation.exe`。没有 `license.dat` 时会停在激活窗：

1. 窗口上会显示本机**机器码**（一串 GUID）；
2. 把授权码（120 字符，可带连字符）粘进输入框 → 激活；
3. 激活成功后直接进主界面，日志里会有
   `授权状态：Active ... 到期 2026-xx-xx`。

**关于「跳过激活」**：`config.json` 里有个 `SkipActivationInDevelopment` 键，
它**只对本机开发用的 Debug 构建有效**。发布包是 Release 构建，无论把它改成什么都会被忽略，
并在日志里写一行 `config.json 里 SkipActivationInDevelopment=true，但这是 Release 构建，该键已忽略`。
这一条在 2026-11-16 实测过（见 `artifacts/S18-tests.txt`），不是推断。

> 如果日志里出现 `界面自检通过：15 个「选择...」按钮都接上了路径选择命令`，
> 说明界面绑定完好。这句不见了要当故障查（WPF 绑定失败是静默的）。

## 6. 首次必须人工登录 FB（最容易漏的一步）

自动化只复用**已存在的登录态**，不会替你输账号密码，也过不了验证码/2FA。

- **google 通道**：在云主机上新建一个独立配置目录，启动后手工登录一次，然后**关掉**。
  这个目录之后交给程序用（账号清单里的 `user-data-dir`）。
  新建方式见 `accounts-HOWTO.md`「新建一个独立的 Chrome 配置」。
- **bit 通道**：在比特客户端里打开对应窗口，人工登录一次。

**不要在程序的 `user-data-dir` 里同时开着浏览器手工操作**：同一配置目录被两个 Chrome
抢会互相踢掉（这正是 S16 修的那个缺陷）。登录完一定先关掉浏览器。

## 7. 准备数据

照 `accounts-HOWTO.md` 填 `accounts.csv`（改 `accounts.sample.csv` 的名字），放在 exe 同目录，
或在「基础设置」里点「选择...」指到别处。要点：

- 每个账号**独立** `user-data-dir`，不要用日常号；
- `bit` 行填窗口 ID，`google` 行填配置目录，另一列留空；
- 密码只写引用名（`cred://acc01`），真实密码走程序里的「设置密码」入口；
- 「资料修改」七项里要用到的：名称文件（txt，一行一个名字）、签名文件、
  头像/背景图目录、类别（留空按原版落「戏剧」）。

## 8. 跑验收

**按这个顺序跑，不要跳**：前一条通过再跑下一条，失败时才知道是哪一层的问题。
每条只看三样：**状态**、**日志**、**失败截图**。

| 顺序 | 任务 | 通过判据 |
| :-- | :-- | :-- |
| 1 | 打开浏览器 | 能起、页面能加载出 FB、关窗后进程不残留。**这条通了才说明 Chrome + 驱动 + 登录态三层都对** |
| 2 | 视频上传 | 视频真的出现在主页；描述文件整段作为一段描述；定时发布时间正确 |
| 3 | 资料修改 | 七项逐项核对（背景图→头像→发帖设置→粉丝公开内容→签名→类别→主页名字）；主页名字那步要输主账号密码，没配密码会写「需人工确认」，属正常 |
| 4 | 删除消息 | 删除条数与日志一致；cookie 目录只写日志不注入（设计如此） |
| 5 | 组合任务 | 多账号串行；同账号两条任务应**排队**而不是并行 |

第 1 条为什么不直接跳到视频上传：如果选择器或登录态有问题，视频上传会在上传到一半时失败，
你会分不清是「选择器失效」还是「上传逻辑有问题」。先跑最短的一条，把执行链路和 FB 可达性钉死。

**第一轮预期会有选择器失效**：所有选择器是按 2026-11 抓的 DOM 写的，FB 改版就会失效。
现象是「找不到【xxx】按钮」这类失败，改 `Automation/Selectors/FacebookSelectors.cs`。
这是仿制项目的正常代价，不是没做完。

## 9. 时区（容易出错的一处）

「定时发布」是**提交给 FB 的发布时间**，按主页所在时区理解。云主机默认是 UTC，
如果不改，你以为设的是北京时间 20:00，实际可能差 8 小时。

**把云主机时区设为账号常用时区**（控制面板 → 日期和时间），再跑。

---

## 10. 风控注意（决定这轮验收成不成）

- **固定一个地区、一个出口**。不要今天香港明天新加坡；不要把本机代理和云主机混着用。
- **新 IP + 新设备首次登录，大概率要求验证**（手机验证码 / 邮箱确认）。这是账号侧的，
  程序侧无解 —— 所以第 6 节必须人工先登好。
- **第一轮用小号或测试主页**，别直接上主力账号。机房 IP 比家宽更容易被判异常。
- 并发保持 **1**，启动间隔保持默认 3 秒。原版也没有更多风控手段（证据见 S16 第 2 节）。

本次是**包月 1 个月 / 130 元**（到期 2026-12-17 14:28），不是按量计费：

## 13. 已知未验项（不要当成「应该没问题」）

1. **选择器未经真机验证**（全部基于本地仿真页 `FacebookMimicPage`）。
2. **导出文件的 `.txt` 扩展名与编码是从原版推断的**，没在真机上核对过内容格式。
3. **主页名字的预览按钮只认 `button[type='submit']`**，若 FB 改了结构会失败。
4. **对话框行为只有启动自检证明「按钮拿到了命令」**，没有证明「点下去真的弹窗」。
5. **比特通道从未对真比特 API 跑过**（此前只有本地 `TcpListener` 桩）。
6. Chrome 集成测试的**偶发卡死未定位**，全量跑结论暂不可信（单跑该类正常）。
7. 任务清单不持久化，关程序队列清空（原版同样不持久化，待需求方定）。
